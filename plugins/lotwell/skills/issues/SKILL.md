# Issues

If the repository has its own issue template, tell the user that this format will override it before writing.

Write the issue in this format, adapted from Matt Pocock's agent brief:

```markdown
**Category:** bug / enhancement
**Summary:** one line

**Current state:**
**Desired state:**
**Acceptance criteria:**
```

Fill each field only from the source: what the user said, an agreed spec or plan, or observed facts with their source, such as an error, a log, or a link. Write acceptance criteria only when the source states them; a decided implementation constraint goes there as a criterion. Leave out any field the source gives nothing for. Add no interpretations, causes, plans, or questions of your own.
